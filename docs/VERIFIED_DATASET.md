# 人工核對數據的兩種角色

`prelabel/hk/verified.json` 這批人工核對過的標註，同時具備兩個用途，
但**不能在同一輪裡混用**。

## 為什麼不能混用

```
train  ──► 模型學習 ──►  model.pth  ──►  用 train 自己測
                                              ↑
                                    準確率必然虛高
```

模型已經記住這些樣本的答案。用訓練過的數據去測，得到的是「記憶力」，不是「辨識力」。
而且每次改動訓練集，測試集也跟著變，前後的分数根本無法比較。

## 正確分工

| 角色 | 檔案 | 用途 | 能不能改 |
|------|------|------|---------|
| **訓練集** | `train.txt` | 模型學習 | 隨時可加新數據 |
| **凍結測試集** | `test.txt` | 跨版本比較的唯一基準 | **劃定後不再變動** |

凍結名單存在 `test_frozen.json`：

```json
{
 "files": ["...__0__hk.jpg", ...],
 "count": 52,
 "sha256_16": "54ff2c9f32a9c652",
 "seed": 42,
 "frozen_at": "2026-10-29T20:42:57"
}
```

## 使用流程

```bash
# 1. 匯出（首次會自動劃定並凍結測試集）
./venv/bin/python scripts/export_verified_dataset.py

# 2. 之後每次人工核對補了新數據，重新匯出即可
#    測試集沿用凍結名單，新數據只進 train
./venv/bin/python scripts/export_verified_dataset.py

# 3. 訓練（用 train.txt）

# 4. 評估 —— 只跑凍結測試集，並記錄到歷史
./venv/bin/python scripts/eval_on_verified.py --split test --record

# 5. 看歷次分數變化
cat crnn_verified/eval_history.jsonl
```

## 基準分數

`2026-10-29` 首次凍結時的基準（PaddleOCR，52 筆）：

| 地區 | 樣本 | EM | CER |
|------|------|-----|-----|
| 香港 | 30 | 76.7% | 0.100 |
| 澳門 | 13 | 92.3% | 0.026 |
| 內地 | 7 | 85.7% | 0.020 |
| 粵Z | 2 | 100.0% | 0.000 |
| **整體** | **52** | **82.7%** | **0.067** |

之後任何模型都要跟這組數字比。低於它就代表退步。

## 幾個容易踩的坑

**測試集樣本被標成不可用怎麼辦**
凍結名單裡的樣本若在後續核對中被改成 `unusable`，匯出時會提示
「N 筆凍結樣本已不在資料中」。這是正常的，分母會變小；
但要在 `eval_history.jsonl` 裡核對 `n` 欄位，確認比較的是同一個基準。

**想重新劃定測試集**
`--reset-frozen` 可以重劃，但這會讓所有歷史分數失去可比性。
只有在測試集本身被發現有錯（例如混入錯誤真值）時才該用。

**數據太少**

210 筆對訓練來說不夠（訓練主要靠合成數據），但對測試來說已經可用。
52 筆測試集的標準誤約 ±5 個百分點 —— 解讀分數差異時要把這個考慮進去，
1-2 個百分點的變化可能只是雜訊。

**新場景要進測試集嗎**

要，但用新的一份。當你開始采集全新場景（例如夜間、雨天、無人機視角），
舊測試集無法反映新分佈。做法是另開 `test_frozen_v2.json`，
在新場景的數據上建立第二代基準，兩代不要混算。
